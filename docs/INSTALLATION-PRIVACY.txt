Build and installation boundaries

Build only from this application directory. The default-deny .dockerignore
permits an exact list of source files, and Dockerfiles copy explicit inputs.
Downloads, local key files, user credentials, live captures, exported ZIPs,
saved profiles, screenshots, and .setup-cache are not in the build context.
The release build receives the Brutal OP25 application key from a private
GitHub Actions secret, not from source files or user profiles. The public client
image includes that key so users do not need to enter it. No distributed client
can guarantee that an included key stays secret. The build does not include user
passwords, saved profiles, or the SDRplay installer. Each end user still needs
their own eligible RadioReference account. See RadioReference's Database Web
Service API policy: https://support.radioreference.com/hc/en-us/articles/18844460198932-Database-Web-Service-API

Saved profiles live in the separate local brutal-op25-data Docker volume. They are
available to the running receiver, not baked into image layers.
Do not publish a data-volume backup or commit a running container as an image.

The RSP addon is a private local build. Its separate vendor context contributes
only the explicitly named, checksum-verified SDRplay installer. It does not
copy the entire cache. The addon includes proprietary SDRplay software and
must not be published without permission to distribute it.

The guided launchers select the actual connected radio. The Windows launcher
checks the RSPdx-R2 serial before USB forwarding; Downloads are never used to
choose a configuration. SDRplay license acceptance and Windows administrator
approval require the user.

Development status: Windows uses Ubuntu WSL with Docker Engine inside Ubuntu;
native Linux uses its local Docker Engine. Docker Desktop is not a prerequisite.
This is not yet a signed, consumer-ready installer.
CheckOnly makes no installation or USB changes. Real API/service operation,
USB forwarding, control-channel reception, and audio still require validation.
The launchers publish dashboard HTTP (8080) and OP25 audio WebSocket (9000)
on host loopback only. Do not expose either port to a LAN or the internet.
The build patches the pinned OP25 audio WebSocket to accept browser handshakes
only from the dashboard's exact localhost origins; the private SDRplay image
receives the same patched OP25 library. This guards against unrelated websites,
but localhost access is not authentication against other programs on the host.
Treat it as a development boundary, not a multi-user security boundary.
