# Maintainer release and production-testing checklist

The repository and base image are public. These items track remaining
permissions and production validation; they are not installation steps.

- The Brutal OP25-specific RadioReference application key was approved and passed a live AARRS import test. Confirm RadioReference's terms for public distribution before a final production release. Each user must still authenticate with their own eligible account. See the [RadioReference API policy](https://support.radioreference.com/hc/en-us/articles/18844460198932-Database-Web-Service-API).
- Review `tests/live-bexar-system.json` and the screenshots for RadioReference data redistribution rights and any information that should not be published. Moving a fixture into `tests/` does not change its contents or publication status.
- `LICENSE` and `THIRD-PARTY-NOTICES.md` are included in the source and image, with OP25/RTL source and headers retained. For each release, verify the exact tagged image contains those files and the corresponding source/patches remain accessible to recipients; independently review any additional dependencies or copied assets introduced later.
- Verify the public `bootstrap/` installer can fetch the source archive and release image without GitHub, Git, SSH, or Docker account authentication. Local-archive install and failed-update rollback tests passed; still test a fresh Windows machine with no WSL or Docker Desktop, then a fresh native Linux install with no existing Brutal OP25 state.
- Replace the bootstrap commands' mutable `main` source-archive URL with an immutable release tag (or a release asset) and publish a verified source-archive digest. Keep program-file rollback and versioned image rollback tests in that release workflow.
- Test saved-system backup and restore on the release image. The transfer passed with disposable Docker volumes; confirm Windows Documents output, native Linux output, and migration to a second clean machine. Do not restore into an active receiver session.
- Measure compressed release download and disk use. The current local image reports approximately 2.15 GB unpacked; a local `docker image save | gzip -1` stream was about 464 MB (not an exact GHCR transfer size). GNU Radio packages dominate. Do not remove SDR or plotting dependencies until receiver and plot tests prove they are unnecessary.
- Test clean Windows with no WSL or usbipd-win: approve only the guided prompts, restart if requested, and confirm RTL-SDR Blog V4 control-channel lock and browser audio without manual driver commands. Confirm the Start-menu shortcut relaunches the same Ubuntu-local Docker volume.
- Test RSPdx-R2 separately on clean Windows and supported native Linux: conditional SDRplay license, verified vendor download, Windows API/local stream or native-Linux private addon, physical device recognition, control-channel lock, and clear audio. One Windows/WSL live test decoded AARRS Northeast Simulcast through the normal launcher with hundreds of TSBKs and call entries; browser audio and clean-host install are still pending. Do not count a software-load check or OP25 startup alone as reception validation.
- The local Ubuntu WSL Engine smoke test confirmed RTL Blog V4 tuner identification and a short 1 MSPS stream with zero reported loss. A separate temporary AARRS Northeast profile achieved live P25 control-channel lock (WACN 0x91F78, system 0x0D2, site 50.50, NAC 0x3C, roughly 798 TSBKs); its temporary profile was archived after testing. In subsequent tests, the user saw live traffic and confirmed browser audio worked immediately after the startup-volume fix. SDRplay direct USB forwarding was too slow for a 2 MSPS stream. The new Windows-local SDRplay stream decoded the same AARRS site and live calls through the normal launcher. Keep on-air and clean-host tests distinct from these narrower results.
- Test a Blog V3 or older RTL-SDR before claiming its preset hardware-validated; the bundled V4-capable library is vendor-documented as backward-compatible, but that has not been exercised on this project hardware.
